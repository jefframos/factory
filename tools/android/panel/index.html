How to set up RevenueCat (real Google Play purchases)

What it is. RevenueCat sits between the game and Google Play Billing: it checks each purchase on its servers and remembers what's owned, so you don't need a server of your own. Free until $2,500 of revenue a month, then 1%.

You need first: a Google Play Console account with the app created (its package, the app id under Package), and the products made in Play Console › Monetize › Products (their ids as in the game's shop).

  1. RevenueCat project. app.revenuecat.com › new project › add an app › Google Play › its package name.
  2. The public key (goes here). Project › API keys › the Google Play key, starting goog_. Paste it above, Save. It's public: fine in the game.
  3. Service account (RevenueCat's own, never in the game). In Google Cloud Console (the same Google account as Play):
    1. New project, e.g. "wallbreak-revenuecat".
    2. APIs & Services › Library: enable Google Play Android Developer API, Google Play Developer Reporting API, Cloud Pub/Sub API.
    3. IAM & Admin › Service accounts › Create ("revenuecat"), roles Pub/Sub Editor and Monitoring Viewer.
    4. That account › Keys › Add key › JSON: it downloads. Keep it with your upload key's backups; never in the repo.
    (RevenueCat's guide has a script that does these in Cloud Shell: Google Play service credentials.)
  4. Let it into Play Console. Users and permissions › Invite new users › the service account's email (…@…iam.gserviceaccount.com) › Account permissions: View app information and download bulk reports, View financial data, orders, and cancellation survey responses, Manage orders and subscriptions, Manage store presence › Invite. (checklist)
  5. Upload the JSON to RevenueCat: the Google Play app › Service account credentials JSON › Save.
  6. Wait. Google can take up to 36 hours before it works; "invalid" before then is normal. Still failing after: a new JSON key, uploaded again (troubleshooting).
  7. Products in RevenueCat: Product catalog › Products › import them from Play; an Offering with them (products and offerings).

Testing without Play (debug builds). RevenueCat › Apps & providers › Test Store: add products there with the same ids as the game's shop (starter, no_ads, double_cash, auto_hold: non-consumable; medals_20, medals_60, medals_150: consumable) and paste its test_ key above. Run on device / Build APK then show RevenueCat's purchase sheet (succeed / fail / cancel). The AAB always uses the goog_ key: the SDK crashes a release build that has a test_ key.

A build with no key for it (or the game in a browser) has mocked purchases.

Upload key

What is the upload key?

Android apps are signed, so a phone knows an update comes from the same maker. With Play App Signing (on for every new app) there are two keys:

  • The app signing key: Google makes it and keeps it, and signs what players download. You never handle it.
  • The upload key: yours. Every AAB you upload is signed with it, so Google knows it's from you. That's this one.

Where it's used: only here, to sign the AAB (Build AAB). Nothing to add anywhere else: the first AAB you upload in Play Console (Testing › Internal testing › Create release) registers it with Google. Debug builds and Run on device don't need it.

Keep it safe: the .jks file and its password, backed up off this computer (a password manager, a drive). Never in the repo (it's public). Lost, Google can reset it, but you ask and wait a few days.

Play App Signing · Use Play App Signing · Generate an upload key · Lost key: reset

Made with Java's keytool (alias upload, RSA 2048, 27 years). Lose it, and Google has to reset it: slow.
